## 改动清单（6 处）

### 1. `read_quote_meta()` —— 无 frontmatter 时的元信息兜底
- **症状**：抓取产物有两种形态：A 自带 YAML frontmatter；B 无 frontmatter，元信息在正文开头的
  `> 公众号: x / > 发布时间: y / > 原文链接: z` 引用块里。B 形态原版会产出**没有任何
  frontmatter** 的笔记，无法落库。
- **修复**：新增 `QUOTE_KEYS` 键映射与 `read_quote_meta(text)`，返回 `(meta, h1, rest)`；
  识别不出任何键时**原样返回**，避免误删正文引言。同时剥掉正文自带的一级标题（避免与模板 H1 重复）。
- **验证**：`AI Agent 的 Skill 系统设计` 一篇从「零 frontmatter」变为带
  `created` + `tags` 的完整元信息。

### 2. `fence_map()` + `find_promo_sep()` —— 围栏感知的推广截断
- **症状**：原版用 `text.rfind("\n---\n")` 找文末推广分隔线。代码块内部常含 `---`
  （YAML / 命令行 / 分割线注释），`rfind` 会命中**代码块里的** `---`，把正文腰斩。
  实测 `AI Agent`、`Hermes` 两篇被切掉大段。
- **修复**：先扫一遍行，标记每行是否处于 ``` / ~~~ 围栏内；只在**围栏外**找候选分隔线，
  且要求其后内容具备推广特征才截断。
- **验证**：两篇正文完整保留，且推广段仍被正确切除。

### 3. `GLUE_RE` + `IMG_ALT_RE` + `fix_heading_lines()` —— 标题行修正
- **症状**（三种，同一处代码处理）：
  a. **标题-正文粘连**：`## 先定义目标 这句话是正文…`——微信把标题与紧随的正文句并进同一行。
  b. **伪标题降级**：整行是正文，却带了 `##` 前缀。
  c. **Image 脏前缀**：图片 alt 为 `Image` 时，剥掉 `![Image](url)` 后标题只剩
     `Image xxx`（`IMG_ALT_RE` 只吃行首紧邻的 `Image`，实测 `AI Agent` 篇有 2 处）。
- **断点规则**：「汉字 + 空格 + 拉丁字母」是最可靠的分界（正文常以英文术语起头，
  而标题本身不会在汉字与英文单词间断开）。只拆**第一处**，其余原样保留——
  这版规则刻意保守，实测整个语料只命中 1 处真粘连。
- **验证**：`AI Agent` 篇标题与正文正确分离，伪标题降级为正文。

### 4. 两条新增的推广 kill 规则
- **症状**：微信推广段并非都以 `---` 开头，有两种常见形态漏网：
  「**后台私信获取原文**」与「**拓展阅读导航条**」。
- **修复**：在这两类标记处截断（围栏外）。
- **验证**：`思科2026报告…` 一篇的「后台私信」段被切除；`AI Agent` 篇的「拓展阅读」段被切除。

### 5. 引用块 / raw H1 剥离并入主流程
- **症状**：B 形态产物正文开头自带一级标题，与模板注入的 `# 标题` 重复（笔记里出现两个 H1）。
- **修复**：`read_quote_meta()` 一并返回并剥掉该 H1，主流程使用它的结果。

### 6. 截断点与 `---` 模板分隔线的边界修正
- **症状**：callout 元信息块后紧跟模板固定分隔线，原版截断逻辑会把它算进候选。
- **修复**：候选分隔线只在正文区之后参与判定，模板头部不参与。

## 回归验证

- 语料：`output/` 下 **12 篇**（含 code-block 密集篇、图片密集篇、B 形态无 frontmatter 篇）。
- 方法：用修复版重跑转换，与磁盘上由修复版产出的 `.obsidian.md` 逐字节比对。
- 结果：**12/12 逐字节一致**（`created` 字段归一化后比对）。
- 同时对基线版跑同一语料，确认基线在 `AI Agent` / `Hermes` 两篇上确实腰斩——
  即这些修复有实际价值，不是等价重构。
