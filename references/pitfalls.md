# 踩坑记录（实测）

## 1. 中文引号归一化：别用「正则配对 + 循环」

微信公众号抓取结果里，中文左引号常被输出成右引号 `”`，甚至同一篇里左右混用。

**错误做法**：`text = re.sub(r'”([^”\n]{1,90})”', r'“\1”', text)` 并循环到收敛。

后果：第一轮把成对的 `”A”` 修成 `“A”` 之后，文本里剩下的是「右引号开头、下一个右引号结尾」
的孤例。第二轮正则会把跨句的两段文字当成一对强行配对，把不该改的右引号改成左引号。

实例（真实事故）：

```
原文：…让大模型”看整个页面 + 生成点击指令”，慢且贵。…从几个候选里”选一个”，…
一轮后：…大模型“看整个页面 + 生成点击指令”，慢且贵。…从几个候选里“选一个”，…   ✅
二轮后：…大模型“看整个页面 + 生成点击指令“，慢且贵。…从几个候选里“选一个”，…   ✗
```

**正确做法**：中文引号在**一行之内必然成对**，所以按行扫描，遇到引号就按出现顺序交替赋值。

```python
QUOTES = "“”"
def normalize_quotes(line):
    out, toggle = [], 0
    for ch in line:
        if ch in QUOTES:
            out.append("“" if toggle == 0 else "”")
            toggle ^= 1
        else:
            out.append(ch)
    return "".join(out)
```

跳过 ``` 围栏内的行（代码里的引号不能动）。此法对「左引号被写成右引号」「左右混用」
「一行多组成对引号」三种情况都成立。

## 2. 提取 tags：正则要容忍最后一行没有换行符

`re.search(r'^tags:\n((?:- .+\n)+)', fm_raw, re.MULTILINE)` 在 frontmatter 被
`^---\n(.*?)\n---\n` 切出来后，**最后一行不带 `\n`**（切割点把换行吃掉了），于是最后一个 tag
被静默丢掉。

写成 `((?:- .+$\n?)+)` 即可。这个 bug 不报错、只少一个标签，很容易漏掉 —— 落库后务必
确认 tag 数量与预期一致。

## 3. frontmatter 与 H1 之间会多出空行

拼接时若 `fm` 模板已以 `\n` 结尾，又写成 `"%s\n# %s"`，就会在 `---` 和 `# 标题` 之间插一个
多余空行。用 `"%s# %s"` 让 fm 自己的结尾换行承载分隔。

## 4. 图片嵌入必须独占一行

抓取结果常出现 `扫码访问官网👇![](images/img_003.png)` 这种图接在段落末尾。转换时统一替换为
`\n![[images/x.png]]\n`，再靠「3 个以上连续空行收敛为 1 个空行」把多余空行压掉。

## 5. 落库只复制被引用的图片

`output/<目录>/images/` 里通常混着封面图、二维码、活动海报、点赞引导图。这些的引用段落已在
转换阶段被删掉，所以落库时按正文里的 `![[images/xxx]]` 逐个复制即可，不要整目录 copy。
校验脚本会提示「文件多于引用」，那是正常的，不扣分。

## 6. 调用 Windows python 时的路径形式

Git Bash 下给 Windows python 传路径要用 `C:/Users/...`，不要用 `/c/Users/...`（会被歪曲成
`C:\c\Users\...`）。

## 7. 发布日期从哪来

`wechat_to_md.py` 抓出的 frontmatter `date` 常为空。可以从原文 HTML 里的
`var ct = "<10 位时间戳>"` 还原：

```python
m = re.search(r'var ct = "(\d+)"', html)
pubdate = datetime.datetime.fromtimestamp(int(m.group(1))).strftime("%Y-%m-%d")
```

拿不准时把日期留空，好过写错。

已实测：`var ct` 与原文页面上显示的发布时间（精确到分钟）一致，可信。

## 8. 微信会限流，别连着抓

同一篇文章短时间内重复 `requests.get` 会撞 `SSLError: UNEXPECTED_EOF_WHILE_READING`。
抓取脚本本身只请求一次，正常流程不会触发；但如果为了补日期 / 做 Tier-2 对照又去拉一遍，
中间夹一次 WebFetch 或隔一会儿再试即可，不要写重试循环硬刚。

## 9. Tier-2 对照的性价比比想象中高

Tier-1 只能证明「结构完整」，证明不了「内容没漏」。做一次 WebFetch 拉原文逐段对照，成本
只有一次请求，却能同时拿到三样东西：

1. **零遗漏确认** —— 把原文段落按序列出，与成品逐段打勾。2000~5000 字的公众号短文很快能对完。
2. **引号修正的验证** —— 原文里 `”` 和 `“` 的混用现场一目了然，能确认归一化方向对不对。
3. **发布时间的独立佐证** —— WebFetch 常能直接读到「2026年9月23日 07:10」这类时间戳，
   与第 7 条的 `var ct` 互为印证。

所以只要文章不长，别省这一步。

## 10. 图片链接可能带 title 属性（静默失效级）

微信偶尔在图片 URL 后附一个 title，值是 `undefined`：

```
![](images/img_000.png "undefined")
```

若正则写成 `\(images/([^)]+)\)`，捕获组会把 ` "undefined"` 一起吞进去，得到不存在的文件名
`img_000.png "undefined"` —— 不报错、图挂了。必须写成：

```python
r'!\[[^\]]*\]\(images/([^)\s]+)(?:\s+"[^"]*")?\)'
```

另外 alt 文本有两种形态：空 alt（`![](...)`）和 `![图片](...)`，用 `[^\]]*` 一并覆盖。

## 11. 反斜杠转义残留

| 形态 | 处理 |
|------|------|
| 独占一行的 `\` | 删行 |
| `change\_cert` | 还原为 `change_cert` |
| `\**加粗\**` | 还原为 `**加粗**` |

**不要无脑 `re.sub(r'\\', '', text)`** —— 会把 `C:\Users` 这类合法路径一起毁掉。
只在「反斜杠 + 标点/下划线」时还原：`re.sub(r'\\([_*\[\]()#!`>+\-.])', r'\1', text)`。

## 12. 加粗标记会被微信按 token 切开

原始 HTML 里一段连续加粗若被拆成多个 `<strong>`，转出来就是：

```
**3.****公告意外：7****月30****日发布**
```

合并方式：去掉**行内**连续的 4 个星号，即 `(?<=\S)\*\*\*\*(?=\S)` → 空串。
`(?<=\S)...(?=\S)` 边界不能省，否则会误伤独占一行的 `****`（Markdown 水平分割线）。

执行顺序：这条要在 **PART 标记清理之后**跑。

## 13. 机构文的 PART 标记与章节编号

券商/机构报告常见结构：

- `**PART**01**` / `**PART****02**` / `**PART02**` → 整块删除（章号已体现为标题）。
  正则 `\*\*PART\*{0,4}\s*\d+\*{0,4}[ \t]*\n?`。
- `**01**` 独占一行 + 下一行 `**章节名**` → 合并为 `## 01 章节名`。
- `**风险提示：**xxx` → `> [!warning] 风险提示` callout。
- 文首 `**文：xxx**` + `联系人：xxx` 若与顶部 info callout 重复，删除。

标题层级还可能遇到下面这些（因文章而异，按需取用，**先长后短替换**）：

| 原文形态 | 目标 |
|---|---|
| `- 1.1.1 标题` | `#### 1.1.1 标题` |
| `- 1.1 标题` | `### 1.1 标题` |
| `#### **引言**` | `## 引言` |
| `## **1、小节名**` | `### 1、小节名` |
| `## **无编号加粗段**` | `**无编号加粗段**`（还原为段落） |

⚠️ 先替换 `x.y.z` 再替换 `x.y`，否则 `### 1.1 xxx` 会把 `1.1.1` 的前缀吃掉。

## 14. 空引用行直接删

`^>[ \t]*$`（微信留下的空 blockquote 壳）没有任何信息，删掉。

## 15. 封面图堆叠

有的文章首图区是 3~4 张连图（`img_000`~`img_003`）加一段标题文字，属于公众号封面模板，
正文不需要。判断方法：这几张图紧挨在 H1 附近且彼此内容相似，删到只剩第一张或全删。

## 16. vault 根 = 含 `.obsidian` 的目录，本机路径只留一个「本机配置」

落库脚本的 `--vault` 要传 **vault 根**，不是笔记所在的分类目录。

- 默认解析顺序：环境变量 `WECHAT_VAULT` → `scripts/local_config.py` → `~/iNote`。
- ⚠️ 2026-09-23 用户重构过目录：原先 iNote 下还多一层 `知识库`（即 `iNote\知识库\公众号\...`），
  该层**已取消**，现在是 `iNote\公众号\...`。

这类路径变更的隐蔽之处：**改了不会报错**。脚本会老实地在（新建的）旧路径下写出一份笔记，
Obsidian 里却看不到 —— 你会以为同步失败，实际是写到了别处。

所以本机路径只保留**一处权威来源**：`scripts/local_config.py` 里的 `DEFAULT_VAULT`
（该文件已在 `.gitignore` 中）。命令行一律走默认值，**不要**把它复制进 SKILL.md 的示例命令、
记忆文件或临时脚本里，更**不要写回 `sync_to_vault.py`** —— 那会让 `git pull` 次次冲突，
`git push` 还会把你的本机绝对路径公开出去。脚本已加两道保险：
`--vault` 不存在直接 `SystemExit`；存在但其下没有 `.obsidian` 时打 WARN（不拦，兼容非标准 vault）。

## 17. 落库后必须归一化换行符（CRLF 污染）

Windows 下用文本模式写文件（`Path.write_text()` / `open(..., 'w')`）会把 `\n` 翻成 `\r\n`；
而 vault 里既有笔记全是 LF。结果同一批笔记出现两种换行符 —— Obsidian 照常渲染不报错，
但 diff / 版本对比时会整篇标红。

2026-09-23 起 `sync_to_vault.py` 的内联 `create_note()` 已显式用 `open(..., newline="\n")`，
**不会**再产出 CRLF；脚本末尾那句 `\r\n → \n` 归一化保留为保底。如果你另外写脚本落库，
记得自己处理这一步。

顺带一个连带效应：`create_note()` 用**当时时间**重写 frontmatter 的 `created`。所以「重跑落库
应逐字节一致」的回归，要把 `created` 那一行排除后再比。

> 2026-09-23 卸载（改用 kepano/obsidian-skills 的 `obsidian-cli` 做通用 vault 操作），
> 落库逻辑内联进本 skill，行为与上述一致。

## 18. BASE 默认值曾指向死路径（静默重建）

到 2026-09-23，`to_obsidian.py` / `sync_to_vault.py` 的 `DEFAULT_BASE` 仍写死为
`~\WorkBuddy\微信公总号知识库\output` —— 该目录**当日已不存在**（整个
`微信公总号知识库` 不见了）。不传 `--base` 时脚本不会报错，而是用 `mkdir(parents=True)`
把这个死路径**重新建出来**，笔记写进去后 vault 里自然看不到，排查时极易误判为「同步失败」。

处理：两个脚本的 `DEFAULT_BASE` 已改为 `cwd/output`（与抓取器 `DEFAULT_OUTPUT_DIR` 一致），
命令行仍可用 `--base` 覆盖。**BASE 与 VAULT 都不要复制进文档或临时脚本**：`BASE` 跟随
cwd 即可，`VAULT` 放 `scripts/local_config.py`（见第 16 条）。

## 19. 章节标题是样式块，不是 `<h1-6>`

微信很多深度长文的章节标题写成：

```html
<section style="font-size: 17px;font-weight: bold;color: #ff6600;text-align: center">
  <span leaf="">AI推理流量四大核心特征</span></section>
```

markdownify 不认 `<section>` 的样式，会把它压成一行普通段落 —— 结果落库笔记**整篇没有 `##`**，
与 vault 里既有笔记（都是 `## 小节名`）风格不一致，阅读理解层次也丢了。

处理：抓取器 `process_content()` 已加确定性提升规则（见该文件 `# 2) 小标题` 注释）：
内联样式含 `font-weight: bold` 且 `font-size >= 16px`（正文 15px）、纯文本、≤40 字、
不以 `。！？；：` 收尾 → 提升为 `<h2>`。L1(17px 橙) 与 L2(16px 蓝) 统一压成一级 `##`，
与「H1 + 单层 ##」的既定风格一致。

改这条规则前先跑一篇有嵌套小标题的文章回归，确认没把正文里的强调块误判成标题（长度与
句末标点两道闸就是防这个）。
